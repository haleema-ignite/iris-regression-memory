# Contributing

Run `npm run check` before opening a pull request. Changes to contract logic should include a focused unit test. New approved contracts must include a violating fixture, a safe fixture, a role owner, and a review date.

Keep the repository identity-neutral and public-safe. Do not add personal attribution, customer data, credentials, internal hostnames, or copied incident conversations. References should use stable issue keys and pull-request numbers.

Use warning mode while evaluating a new contract. Approval to store a contract and approval to make it blocking are separate decisions.
